# M5 验收记录（终端、人工模式、探索基线）

日期：2026-10-03。规则 `facility-zero/1`，协议 `agent/1`、`observer/1`、`replay/1`，摘要 `run/1`。环境：Windows、全局 .NET SDK 10.0.401、Release、零第三方 NuGet 依赖、Python 3。

结论：M5 的终端渲染、人工模式（含记录与离线核验）与探索基线已实现并通过本机验收（T501–T504 的实现部分）。**尚未**在真实交互终端里肉眼确认画面，回放播放控制（`replay --speed/--pace`）尚未接线——两项都如实列在下面的限制里。

### 探索基线（T504）

- 手工样例 `facility-small.json`：**13 回合最优成功**，`core_hash=a68fe87640e7105142f481a59e77f43bdb854bab61a826e38ae4fd77ae323262`（与独立 Core golden 一致）。
- 固定生成种子（M5 Explorer 检查覆盖 7 个种子 + 空工作目录隔离运行）：**9/9 通过**，每个都要求真实 `kind=success` 且记录 `verify` 为 `valid=true`。
- 修复前的实测（12 个种子）为 10/12，seed 2 与 6 在 512 回合内耗尽：记录显示连续 458–508 步重复同一个 `interact-east`，即“相邻有闭门就交互、失败后没有转成负事实”的活锁。修复后该活锁消失；`_action_allowed` + `_remember_failure` 保证同一状态不会再次发出刚失败的动作。

### 人工模式（T503 的实现部分）

重定向输入下 `play --scenario <13 回合场景> --plain --record <新文件>`：退出码 0，stdout 恰好一行 `run/1` JSON（`kind=turn_limit`、`tick=13`、`agent_name=human`），随后 `verify` 该记录返回 `valid=true`、`status=completed`、`tick=13`——人工记录可离线核验。stdout/stderr 均无 ESC，按键图例在 stderr。

### 终端与用法错误

`run --tui` 在 stdout 被重定向时退出码 2 且 stdout 为空（`--tui requires an interactive terminal`）；`--tui` 与 `--observer-stdout`/`--headless` 组合退出码 2；`play` 缺 `--scenario` 或未知选项退出码 2 且不写 stdout。

## 独立审查与修正

用免费额度的 ecnu-max 委派了两个只读审查（代码 + 文档），主代理逐条复核：

| 结论 | 内容 | 处理 |
|---|---|---|
| 成立（已修） | `play` 模式下 `TerminalObserverSink` 的 `ReplayControls.PollInput` 与 `HumanInput.ReadStep` 在**不同线程读同一个控制台**：方向键可能被 sink 吞掉、`q`/Esc 可能提前终止视图而人类动作丢失 | 新增 `interactiveControls` 开关；`play` 传 `false`（不轮询、不暂停、不写提示），只有 `run --tui` 独占控制台输入 |
| 未验证疑虑 | 暂停/慢消费可能填满有界队列并触发 `resync_required`，视图中断但运行仍返回 0 | 保留为已知行为：sink 会报 `observer_error` 到 stderr；未构造出稳定复现 |
| 未验证疑虑 | `HumanSession` 注释“no partial step is committed”在 `Game.Step` 与记录 `StepAsync` 之间的取消窗口内不严格成立 | 记录为限制；该窗口只有一次迁移，不会崩溃 |
| 成立（已修） | 文档仍写“M5 待实现”“重定向场景用 useColor:false”等与实现不符的表述 | 更新 README、`docs/terminal.md`、`docs/project-plan.md` 第 9 节 |

## 限制与下一阶段

- **画面未肉眼确认**：TerminalView 有 106 项隔离行为检查（逐字符断言、96 种尺寸、纯文本无 ESC、真实冻结 fixture 渲染），但没有任何人在真实终端里看过 `run --tui` 的观感；颜色只做过结构与可见宽度校验。
- **回放播放控制未接线**：`ReplayControls` 已实现并用于 `run --tui`，但 `replay` 仍是纯粹导出（无 `--speed`/`--pace`、无终端画面）。这属于 T503 的剩余部分。
- `play` 有意不提供暂停/单步/倍率：人工局由玩家自己的节奏驱动，与 `--tui` 的观察者控制互斥（见上面的并发缺陷）。
- 跨平台（Linux）、完整进程树清理、`scripts/verify.ps1` 等 pwsh 7 黑盒脚本的重跑仍是 M6 门槛。
