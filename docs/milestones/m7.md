### 实现的规则

- **严格座次轮转**：`OwnerSeat = tick % N`，一步恰好一 tick；`MaxTicks` 是**共享的席位回合数**（N 席共用该预算）。非本席回合调用 `Step` 抛 `InvalidOperationException` 且不改动 tick/位置/库存/哈希；终局后所有席位都抛。
- **门卡与门共享**：任一席位拾取门卡即全队持有；任一持卡席位可开门；门不再关闭；门卡不消耗——与 v1 语义一致。
- **核心有唯一携带者**：拾取核心的席位成为持有者，第二个席位无法再拾取，持有者不会转移。
- **协作终局**：**携带者本人**站上出口 → 全员成功；否则由共享预算截断；最后允许回合的成功优先于截断。
- **信息隔离**：`Observe(seat)` 只给该席位自己的可见格、自己是否为携带者（`HasCore` 仅对持有者为真，`HasKey` 共享）。

### 冻结向量（`core-state/2`）

```text
initial (无人持核心)  d9e985318403061163239a6e14178acb4a2d3bbec084e994f83c66842ceb6ac5
carrier (席位1持核心) 348965c6bce99d8eb3887288421ce7ac086c50e149976743c20f7952533dd631
success (携带者在出口) aa64b569d1d718a5ee227386a93a280829f766160102a2e1f0589ff194231bf8
```

`core-state/2` 在共享字段里用**携带席索引 Int32**（-1 = 无人）取代 v1 的 `has_core` 布尔，因此"无人 / 席位0 / 席位1"在坐标全相同时也能被区分。

## 审查发现并修正的规则漏洞（本轮最重要的一条）

首版实现把核心也当成"全队共享"，成功判定为 `_hasCore && _positions.Contains(Exit)`。这在 2 席下可被直接利用：**让一个队友先站到出口，另一个席位独自取核心，核心从未被带回出口就会立刻获胜**——任务的返程要求被绕过。

修正为"单一携带者"规则（见上），并新增三项回归检查：

1. `A teammate standing on the exit does not end the episode`：严格复现漏洞场景——席位 1 走到出口、席位 0 拾取核心后，断言 `Episode` 仍为 null、`CoreHolder == 0`、阶段为 `return_to_exit`，随后携带者回到出口才成功。
2. `The core has exactly one carrier`：第二席不能重复拾取，持有者在终局前不变，`Observe` 只对持有者报 `HasCore`。
3. `The encoding distinguishes nobody / seat 0 / seat 1 carriers`：坐标全相同时三种持有状态产生三个不同哈希。

该修正影响了 `core-state/2` 的字段，因此冻结向量已重新生成（Python 与 C# 同步），并在提交前完成——`core-state/2` 尚未发布，无兼容性代价。

### 性能边界（重要，写入限制）

双席位全状态协作搜索随地图增大呈平方级膨胀：21×13 的地板格数使部分种子在 50k 状态上限内无法完成，生成耗时可达数分钟。因此**多人生成的默认棋盘为 15×9**（可用选项放大，规则本身不限尺寸）。求解器的状态键最初用字符串且因 `ImmutableArray` 结构相等比较的是引用而非内容而失效率——已修为内容比较。
